# JS 注释做法

注释符号受前端 eslint 限制，实测见 `symbol-rules.md`；文件头见 `header-comment`。

## 单行注释

- 只在非显然处写一行 `//`，讲"为什么"不讲"做什么"；`<!-- -->` 同样一行，最多两行。
- 组件文件注释宜少；模板里只在结构不直观时写，说明插槽用途或条件渲染的业务原因，不给每个 `div` 加说明。
- 该删：`// ===== 接口列表 =====`、`// 定义响应式变量`、`// 遍历数组`。
- 该留：`// 后端返回 0 表示本级，前端下钻时要区分"无下级"和"本级"`。

## 函数 JSDoc

- 简单函数不写；只在"为什么"非显然或签名表达不了口径时写（单位、边界、兼容、坑），一行优先。
- `@param` 只在参数含义超出参数名时写（单位、口径、默认值）；`@returns` 只在空值或无数据的语义要说清时写。
- 不为"看起来规范"给每个函数补 JSDoc。
- 该删：`/** 获取列表 */`，以及带 `@author`/`@since` 的 JSDoc——版本库已记录。
- 该留，压成一行：`/** 区县级账号无下级区域时回退统计本级 */`。

```js
/**

 * @param {number} regionCode 区域码，0 表示本级
 * @returns {number} 汇总金额，无数据时返回 0
 */

```
