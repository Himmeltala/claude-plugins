# 会话标题

Claude Code 内置的 AI 标题只在首轮生成一次，之后全程冻结；本插件用 `UserPromptSubmit` 钩子按对话内容重写。回答这类问题时，先分清是内置行为还是插件行为。

## 插件做了什么

- 用户每次提交消息时，钩子回填上一次在后台生成好的标题，并在计数到间隔时派一个后台任务重新概括当前会话。
- 标题滞后一轮：后台概括要三秒上下，放在钩子里同步等就是把延迟加在提问上。
- 用户 `/rename` 过的会话永久停手。判据是 transcript 里最后一条 `custom-title` 与插件上次回填的值不同；钩子设置的标题同样写成 `custom-title`，两者在文件里没有区分。
- 清过缓存的老会话会被当成用户手动命名过，同样停手。

## 开关

- `SESSION_NAMING_OFF=1`：本会话按不生成处理，已回填的标题保留。
- `SESSION_NAMING_INTERVAL=<次数>`：每隔几次提问重新概括，默认 4。
- `SESSION_NAMING_MODEL=<模型>`：后台概括用的模型，不设就用当前默认模型。

三个都是环境变量，写在启动 `claude` 的那个 shell 里才生效。

## 答不上来时

插件只在装了以后的新会话生效，重启会话才会加载钩子。改过插件源码要重新 `claude plugin update`，缓存目录不会自动跟随源目录。
