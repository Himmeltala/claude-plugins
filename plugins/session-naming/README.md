# session-naming

按对话内容自动更新会话标题。

## 解决什么问题

Claude Code 自己会给会话起标题，但只在首轮生成一次，之后全程不变。长会话做到一半换了主题，`/resume` 列表里还挂着开头那几轮的名字。本插件在后台按间隔重新概括，通过官方钩子字段把新标题写回会话。

## 行为

- 用户每次提交消息时，钩子先把上一次生成好的标题回填给会话，再判断要不要重新生成。
- 重新生成走一次无状态的 `claude -p` 调用，读首条提问与最近十二轮对话，产出十几个字的短语。
- 标题写成 `项目名:标题`，项目名取会话工作目录的最后一段（如 `aqsj-backend-tg:作业点查询接口`）；取不到目录名时只写标题。前缀不占标题的字数上限。
- 标题滞后一轮：生成要三秒上下，同步放在钩子里就是把延迟加在提问上，所以放到后台。
- 只有用户亲自提交的消息才触发；loop、定时唤醒、消息注入这类轮次不算。
- 用户 `/rename` 过就永久停手。钩子设置的标题同样写成 `custom-title`，与 `/rename` 的结果在 transcript 里没有区别，只能拿最后一条记录和插件自己上次回填的值比对。清过缓存的老会话会被当成手动命名过，同样停手。
- 建会话时继承来的标题不算手动命名。`/clear` 或从已有会话续开时，Claude Code 会把原会话的标题写进新文件的第一条记录，新会话一出生命字就和旁边那个一样；插件认出这种情况后照常生成自己的标题，不让两个会话一直同名。

## 开关

三个环境变量，写在启动 `claude` 的那个 shell 里：

| 变量 | 作用 | 默认 |
|---|---|---|
| `SESSION_NAMING_OFF=1` | 关掉生成 | 不开 |
| `SESSION_NAMING_INTERVAL` | 每隔几次提问重新概括 | `4` |
| `SESSION_NAMING_MODEL` | 后台概括用的模型 | 当前默认模型 |

## 局限

- 只在终端 CLI 下可靠。VS Code 扩展自己的 AI 标题可能覆盖钩子设置的值。
- 需要 `python3`。没有时钩子静默放弃，不报错也不影响提问。
- 状态文件按会话存在插件数据目录里，清掉就会重新开始。

## 安装

```bash
claude plugin install session-naming@himmeltala-claude-plugins
```

钩子在会话启动时加载，装完重开一个会话才生效。改源码后要 `claude plugin marketplace update` 再 `claude plugin update`，缓存目录不会自动跟随源目录。
