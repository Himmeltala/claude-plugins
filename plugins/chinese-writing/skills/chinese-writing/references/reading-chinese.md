# 读中文需求

中文省略多，靠语境补。别按英文语序反推，也别把省略当"意思明显"直接开工。

## 一、补出省略

"改一下"缺改哪儿，"优化一下"缺指标，"顺手清理"缺范围，"看着办"缺标准，"不对"缺现象。

缺就复述确认："你的意思是把 xxx 改成 yyy，范围只限 zzz，对吗？"这比做错返工便宜。

## 二、一词多义先对齐

接口（HTTP / Java interface / 第三方）、清理（删注释 / 删文件 / 清库）、提交（git / svn / 表单）、表（数据库表 / 前端表格 / Excel）、版本（版本库 / 软件 / 插件）、字段（数据库列 / Java 属性 / 表单）、上线（测试 / 生产）。

项目与目录能消歧；不够就问，不要挑一个先做。

## 三、条件在前，结论在后

"工作副本落后就别提交"是先条件后结论，不要读反。"A 不是 B 的"不等于"A 不是 B"，"除了 A 都行"与"A 除外也行"相反。

## 四、否定词漏读代价最大

不、别、禁、免、除非、勿、无需、不必，漏一个整个需求反过来。含否定的需求，动手前把否定部分单独复述一遍。

## 五、问法与范围

- 一次问一个，带选项与判断，不空手问。
- 用户说的范围就是范围："顺手清理"只指本次碰到的文件，"先看下"是只读。扩展范围先问。
- "看着办""大概""差不多"是留余地，不是授权。按最小改动做，并说明按什么理解做的。
